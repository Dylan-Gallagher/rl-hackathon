The bet

CTF is not a single clever prompt. It’s a few good ideas among many dead ends.

  • Per-turn alloy (XBow): one agent loop; each turn a different model. They don’t know they’re sharing a transcript.
  • Racing ensemble: k sandboxes, first verified flag wins.
  • Distill successful traces into one open-weights student (SFT, then GRPO if we have GPU hours).

Metrics in one slide

Pass@1

Try once. Did we get the flag?

Pass@4

Try four times. Did any attempt get the flag?

Maj@4

Do 3 of 4 attempts solve? (consistency)

Flags self-verify, so Pass@k is the metric that matches the product. Maj@k is the honesty check.

Locked eval — 20 crypto tasks, k=4

Pass@1Pass@4Maj@4
7B base 20.3% 26.3% 21.1%
7B SFT v1 (117 traces) 17.7% 42.1% 10.5%

Lead with Pass@4: +15.8 points. Coverage almost doubled.
Pass@1 / Maj@4 dipped — thin SFT spread the mode; it did not sharpen a single reliable strategy.

How to read that

Same task, 4 attempts

  base   ✗  ✗  ✗  ✗     Pass@4 no
  SFT    ✗  ✓  ✗  ✗     Pass@4 yes   Maj@4 no

SFT found flags on tasks the base never solved in four tries — but often only once out of four. That’s why Pass@4 up, Maj@4 down. Next step after more data / GRPO: raise Maj@4 without giving back Pass@4.

Techniques (checklist)

  • Per-turn alloy — weighted random teacher each turn (XBow).
  • Race — isolated envs, first verified flag, cancel the rest.
  • Assistant-only SFT — mask observation/tool tokens.
  • LoRA — 7B on one 5090, minutes not hours.
  • Flag-as-reward — binary verifier; DAPO drop all-0 / all-1 groups (GRPO ready).
  • Curriculum band — keep tasks with 5–40% student pass rate.
  • Hard REPL — models cannot cat the flag file.
